# Ballast Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A menu bar macOS app that breaks disk use down by developer concern (Ruby, Node, Homebrew, Docker, Xcode, project leftovers, caches, databases, AI models, apps, large files) and removes unused items the way the owning tool would.

**Architecture:** A SwiftPM package with two products:
- `BallastCore` is a UI-free library. Each concern is a `Provider` that discovers items, measures them, marks what's in use, and turns a selection into a reviewable `Plan` of steps. An `Executor` runs approved plans through a `CommandRunner` and the Trash.
- `Ballast` is the SwiftUI app. It has a `MenuBarExtra(.window)` popover and a main `Window`, both driven by an `@Observable` `AppModel`.

**Tech Stack:** Swift 6 (language mode 6), SwiftUI, Observation, swift-testing, ServiceManagement, UserNotifications. No third-party dependencies. Built with the Command Line Tools and `make`; there's no Xcode project.

**Spec:** `docs/superpowers/specs/2026-10-27-ballast-design.md`

## Global Constraints

- macOS 14 minimum: `platforms: [.macOS(.v14)]`. Swift tools version 6.0.
- No third-party packages.
- Builds with Command Line Tools only. `make` must fail with a clear message when `swift --version` is older than 6.0.
- The app bundle: id `za.co.linear.ballast`, `LSUIElement` = true, signed ad hoc (`codesign --force --deep -s -`). It's installed to `~/Applications/Ballast.app`.
- No permission prompts at launch or during background scans:
  - Never read `~/Documents`, `~/Downloads`, `~/Desktop`, `~/Movies`, `~/Library/Containers/*` or `~/Library/Group Containers/*` during a scan the user didn't start for that concern.
- Sizes are allocated bytes (`totalFileAllocatedSize`), with hard links counted once. Sizes are shown with `ByteCountFormatter` (`.file` style).
- Files are removed only by moving them to the Trash (`FileManager.trashItem`), or by a tool's own command. There is never an `rm -rf` in code paths that act on user files.
- Risk levels, with fixed copy: `Regenerable`, `Review`, `Your data`.
- Persistence:
  - Summary: `~/Library/Application Support/Ballast/summary.json`
  - Settings: `UserDefaults` suite `za.co.linear.ballast`
  - Action log: `~/Library/Logs/Ballast/actions.log`
- Defaults: rescan every 24 h; low-space warning below 10% free; a project is idle after 60 days; a large file is over 500 MB.
- Tests never touch real user locations. Every provider takes an `Environment` whose `home` and tool roots point at a temporary fixture tree.

## Review Focus

1. **Paths with spaces or quotes** (`~/Library/Application Support/...`) in generated commands must be shell-quoted, so the command acts on exactly that path. Covered in Task 3 (`shellQuote`) and Task 11.
2. **A tool that's missing or fails** (`rvm` not on PATH, `ollama` server down, `docker` daemon off) shows as a failed step with stderr. It must never crash or report success. Ollama-down falls back to trashing the model files. Covered in Tasks 3, 9 and 11.
3. **Permission denied partway through a walk:** the item is marked `locked` and its size is "at least N". It must never show 0, or a size presented as complete. Covered in Task 2.
4. **Symlinks:** loops, links into other volumes, and `/usr/local/bin` links pointing at deleted apps are never followed when measuring. A dangling link is reported as a leftover, not an error. Covered in Tasks 2 and 6.
5. **Things change between scan and removal:** a version becomes the default, a worktree gets uncommitted changes, a server starts. Refusals and in-use checks are re-run right before execution, and they abort that step. Covered in Task 11.

- Rules:

  7. `.copyToTerminal` gives `shown`.
